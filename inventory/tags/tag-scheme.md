# NFC Tag Scheme

Tags carry a public HTTPS URL. No custom app is required; either phone opens the link in its browser.

## Tag types

| Type | Payload | Where it goes |
| --- | --- | --- |
| Bin | HomeBox location URL generated by HomeBox | On the bin |
| High-value item | HomeBox item URL | On the item or its case |
| Pantry product | `https://grocy.gcelik.dev/product/<product-id>` | On the product's shelf/bin |
| Action | Home Assistant tag URL | Optional command card |

## How to get URLs

### HomeBox bin

1. Create the location in HomeBox.
2. Open the location.
3. Use HomeBox's label/QR action to get the location URL.
4. Use the label's URL field as the NFC payload.

### HomeBox high-value item

1. Create the item and assign it to a location.
2. Open the item.
3. Copy the item URL, for example `https://homebox.gcelik.dev/item/<uuid>`.

### Grocy product

1. Create the product in Grocy.
2. Open the product and note the numeric ID in the URL.
3. The tag URL is `https://grocy.gcelik.dev/product/<id>`.

## Rules

- Use the public HTTPS URL, not an internal IP or ingress node port.
- Do not put Home Assistant ingress URLs on tags.
- Do not encode credentials or private notes in the URL.
- Keep the URL stable. Renaming is fine; changing the record ID breaks the tag.
- A tag UID is not authentication. Anyone who can tap the tag sees the same page.
- Do not lock tags until the final domain, path, and record are confirmed.
- HomeBox is the source of truth for bins and durable items. Grocy is the source of truth for pantry products.
- Do not duplicate the full HomeBox location tree in Grocy. Use a handful of Grocy locations such as `PANTRY`, `FRIDGE`, and `FREEZER`.
